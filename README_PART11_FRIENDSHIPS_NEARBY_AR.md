# الجزء الحادي عشر — الصداقة والهوية والظهور القريب

## التعديلات في هذه النسخة
- توليد معرّف محلي ثابت لهذا التثبيت وحفظه إذا لم يكن موجودًا، بدل ترك كل تثبيت جديد يستخدم القيمة العامة `blousab-user`.
- منع حفظ طلب صداقة وارد مكرر من المرسل نفسه، حتى لو وصل الطلب بمعرّف طلب مختلف نتيجة إعادة الإرسال أو اكتشاف أكثر من مسار.
- منع قبول علاقة صداقة يكون الطرف فيها هو المستخدم نفسه.
- جعل إضافة الصداقة مقتصرة على طلب صداقة وقبول صريح؛ اكتشاف البلوتوث وحده لا يضيف صديقًا ولا يبدأ محادثة تلقائيًا.
- إبقاء اكتشاف البلوتوث قائمًا على عناوين الأجهزة الفريدة، مع توضيح أن الجهاز المكتشف ليس بالضرورة مستخدم بلوساب مؤكدًا قبل تبادل بيانات التطبيق.

## الحدود التي يجب عدم الخلط بينها وبين الميزات المكتملة
- معرّف المستخدم هنا محلي للتثبيت؛ ليس حسابًا سحابيًا ولا يثبت هوية الشخص عبر إعادة تثبيت التطبيق أو أجهزة متعددة.
- طلبات الصداقة والردود الحالية تعتمد على وصول الرسائل عبر الشبكة المحلية، وليست خدمة طلبات موثوقة عبر الإنترنت.
- إعداد الظهور القريب موجود مسبقًا، لكن Android يقيّد مدة اكتشاف Bluetooth ويطلب إذن النظام. تعطيل الظهور لا يعني محو الصداقات المحفوظة.
- لا تعرض هذه النسخة حالة «متصل الآن» موثوقة؛ اكتشاف جهاز لا يكفي لإثبات أن المستخدم متصل بالتطبيق.
- توحيد الشخص نفسه بين Bluetooth وWi-Fi يتطلب معرّف تطبيق موثوقًا يُتبادل عبر مصافحة التطبيق؛ عنوان Bluetooth واسم الجهاز وحدهما لا يكفيان.

## الاختبار
لم يتوفر Flutter/Dart لتشغيل analyzer أو بناء APK، ولم يتم اختبار أجهزة فعلية. يلزم اختبار طلب الصداقة والقبول والرفض وتبديل الظهور على جهازين، مع التأكد من استمرار الرسائل والقصص والمنشورات.
