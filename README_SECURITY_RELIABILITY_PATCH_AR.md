# بلوساب — رقعة أولى للأمان وحدود الشبكة

## التعديلات المنفذة في هذه الرقعة
- إضافة حد أقصى 1 MiB لإطار TCP مفصول بسطر؛ الاتصال الذي يرسل إطارًا بلا نهاية أو أكبر من الحد يُغلق بدل تجميعه بلا حدود.
- رفض الإرسال عبر TCP إذا تجاوزت الحزمة الحد نفسه.
- تقوية سياسة الترحيل: التحقق من حجم JSON، وطول المعرّفات، وصحة الوقت، وعدد القفزات، وشكل مسار الترحيل، وعدم تمرير الرسالة عبر جهاز موجود مسبقًا في المسار.
- عدم تسجيل معرّف الرسالة ضمن سجل إزالة التكرار إلا بعد اجتياز التحقق الأساسي، لتجنب تسميم السجل بحزمة غير صالحة.
- إضافة اختبارات وحدة لسياسة الترحيل.

## حدود لا تزال قائمة ويجب عدم إخفائها
- هذه الرقعة لا تضيف توقيعًا تشفيريًا للهوية ولا تشفيرًا طرفًا إلى طرف؛ حقول senderId وrelayPath لا تزال بيانات غير موثوقة ما لم تُربط بتحقق تشفيري.
- لا تزال حماية PIN القديمة وتخزين بيانات التطبيق بحاجة إلى ترحيل مستقل واختبار توافق يحافظ على إعدادات المستخدمين.
- حد TCP لا يعني أن كل مسارات Bluetooth أو كل معالجات المرفقات أصبحت محمية؛ يجب تطبيق فحص الحجم والتحقق من الهوية عند نقطة استقبال كل ناقل، وقبل فك Base64 أو الكتابة على القرص.
- لا تنشئ هذه الرقعة Wi-Fi Direct أو خدمة Android أمامية، ولا تجعل الشبكة تعمل تلقائيًا بعد قتل التطبيق.
- لم يتم تعديل توقيع release أو إزالة الأذونات بعد؛ يتطلب ذلك قرار نشر واختبارات منفصلة.

## التحقق
- أُنشئت اختبارات `test/relay_policy_test.dart`، لكنها لم تُشغّل لأن Flutter/Dart SDK غير متوفر في بيئة التحرير.
- يجب تشغيل `flutter pub get`, `flutter analyze`, `flutter test` وبناء APK ثم اختبار جهازين/ثلاثة أجهزة فعلية قبل اعتماد الرقعة.
