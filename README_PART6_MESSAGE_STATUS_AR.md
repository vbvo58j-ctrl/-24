# الجزء السادس — حالات الرسائل (بلوساب)

## التغييرات
- إضافة حقل `isRead` مع حفظه واستعادته ضمن سجل الرسائل.
- توحيد تحديث الحالة في `MessageStore` مع انتقال أحادي الاتجاه: `pending` ثم `sent` ثم `delivered` ثم `read`؛ لا تسمح التأكيدات المتكررة بخفض الحالة.
- حالة `sent` تعني أن كتابة البيانات على وسيلة النقل نجحت، ولا تعني الاستلام.
- `delivery_ack` يرفع الحالة إلى `delivered` فقط بعد حفظ الرسالة في جهاز المستلم، ويرتبط بمعرّف الرسالة والمحادثة والمستلم.
- `read_ack` يرفع الحالة إلى `read` فقط للرسالة الصادرة المطابقة في المحادثة نفسها.
- عندما تكون المحادثة مفتوحة وتصل رسالة وتظهر للمستخدم، يرسل التطبيق تأكيد قراءة بالإضافة إلى تأكيد الاستلام. وعند وصول نسخة مكررة، يعاد إرسال التأكيدين دون إضافة نسخة جديدة.
- واجهة الرسائل الصادرة تعرض ✓ للإرسال، و✓✓ بالرمادي للاستلام، و✓✓ بالأزرق للقراءة، مع نص حالة واضح.
- تحفظ الحالات في سجل الرسائل المحلي.

## القيود والاختبارات
- لم تتوفر أدوات Flutter/Dart في بيئة التعديل، لذلك لم يُشغّل `flutter analyze` أو اختبار بناء APK.
- يلزم اختبار عملي على هاتفين للتحقق من توقيت التأكيدات، خصوصًا عند انقطاع الاتصال.
- تأكيد القراءة يُرسل أثناء عرض المحادثة المفتوحة؛ لا توجد خدمة خلفية مضمونة لتسجيل القراءة عندما تكون المحادثة مغلقة.
- هذه التأكيدات ليست تشفيرًا أو إثبات هوية تشفيريًا؛ يلزم تنفيذ توثيق/تشفير الطرفين بصورة منفصلة قبل استخدام الرسائل الحساسة.
